# LibraVerse test cases (TC-01 to TC-12)

Every key test case from the project report, where it is automated, and how to
check it by hand. Run everything with `npm test` from the repository root.

| ID    | Scenario                                                 | Expected result                                                                                      | Automated test                                                                                                                                                                                                             | Manual check                                                                                                                                    |
| ----- | -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| TC-01 | Member pays for a plan online and the payment succeeds   | Admin sees Payment Successful, member sees Membership Activated and the card reveal, receipt emailed | `server/tests/payments.test.ts` › TC-01 (webhook → membership, receipt email with PDF, live `payment:updated` to member and staff sockets); `client/src/features/payments/Payments.test.tsx`                               | Razorpay test mode: Member → Home → Buy; pay with test card `4111 1111 1111 1111`. Needs the webhook to reach the API (tunnel or deployed URL). |
| TC-02 | Member lets the payment timer run out                    | Payment Expired; no membership                                                                       | `payments.test.ts` › TC-02 (expiry job; a late capture is auto-refunded and never activates)                                                                                                                               | Start a payment and close the Razorpay window; after 10 minutes the request shows Expired.                                                      |
| TC-03 | A fake success message without a valid webhook signature | Rejected; payment stays Pending                                                                      | `payments.test.ts` › TC-03 (wrong secret and unsigned bodies → 400, payment still `pending`, no plan)                                                                                                                      | `curl -X POST .../api/webhooks/razorpay/<libraryId> -d '{...}'` → 400 `INVALID_SIGNATURE`.                                                      |
| TC-04 | Librarian records a cash payment                         | Membership activated; receipt; audit entry with the librarian's name                                 | `payments.test.ts` › TC-04; `Payments.test.tsx` › records cash                                                                                                                                                             | Counter → scan card → Collect payment → Cash received → Audit log shows `payment.cash` with the librarian's name.                               |

Also covered: auth (rotation, reuse detection, OTP reset, staff 2FA, Google),
RBAC on every route, the audit log's append-only rules and hash chain, AES-GCM
secret encryption, catalog/CSV/ISBN/QR stickers, reports and exports, the AI
assistant's tenant-scoped tools, and the Socket.io handshake.
